      Segment Tree Complexity & Properties

      Operation Complexity Notes

      What a Segment Tree Stores

      Each leaf holds a single array element A[i] covering interval [i..i]. Every internal node splits [lo..hi] at mid = ⌊(lo + hi) / 2⌋ into left child 2·node + 1 ([lo..mid]) and right child 2·node + 2 ([mid + 1..hi]), storing combine(left, right). An array of length n has exactly 2n − 1 populated nodes—so building visits every node once in O(n) time—and 0-based heap indices always fit within 4n flat-array slots.

      The Three Overlap Cases: Full, Partial, and Disjoint

      When querying [l..r] at a node covering [lo..hi], exactly one case applies: Disjoint (hi < l or lo > r) returns the identity immediately without descending; Full overlap (l ≤ lo and hi ≤ r) returns the precomputed node value directly; Partial overlap recurses into both children and combines their answers.

      Why Range Queries Visit Only O(log n) Nodes

      At any depth of the tree, at most two nodes can partially overlap [l..r]—at most one containing the left endpoint l and one containing the right endpoint r. Every interior node between them is a full-overlap base case, and every exterior sibling is a disjoint base case. Because each of those at most 2 partial nodes inspects 2 children, at most 4 nodes are visited per level; with height h = ⌈log2 n⌉, a query visits at most 4h + 1 nodes (4h − 1 for n ≥ 2), which is O(log n).

      Point Update & Associative Combine Modes: Sum vs. Min

      Updating A[i] follows a single root-to-leaf path (O(log n)) and recomputes each ancestor from its two children on the way back up. Any associative operation—where grouping does not change the result, (a ⊕ b) ⊕ c = a ⊕ (b ⊕ c)—works, paired with an identity element (combine(x, id) = x) for disjoint branches: Sum uses a + b with identity 0, while Minimum uses min(a, b) with identity +∞.
