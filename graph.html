      Operation Adjacency List Adjacency Matrix Notes

      Notation: V = vertices, E = edges, deg(u) = degree of vertex u (out-degree deg⫀(u) in directed graphs). Keyboard shortcuts when focus is outside a control or scroll region: Space play/pause, ←/→ step, Home reset.

      Adjacency List vs. Adjacency Matrix Tradeoffs

      An Adjacency List uses O(V + E) space and iterates vertex u’s neighbors in O(deg(u)), making it ideal for sparse graphs (E ≪ V²). An Adjacency Matrix uses O(V²) space but checks whether edge (u, v) exists in O(1) array indexing.

      Undirected Symmetry vs. Directed Asymmetry

      In an undirected graph, edge u — v updates both adj[u] and adj[v], so the adjacency matrix is symmetric (M[u][v] = M[v][u]). In a directed graph, u → v appears only in row u, column v, and mutual edges u → v and v → u can carry independent weights.

      Weighted vs. Unweighted & Why null Means No Edge

      Unweighted edges store 1 (connected), while weighted edges store integer costs in 1–99. Absent edges are stored as null (displayed as ·)—never 0 or −1—because real weighted graphs can have zero-cost or negative-cost edges that must never be confused with “no edge.”

      Ascending Neighbor Order for Traversals

      Keeping every vertex’s neighbor list strictly ascending by vertex ID guarantees deterministic visitation order in BFS and DFS, and deterministic neighbor relaxation order in Dijkstra’s algorithm, so every student traces the same sequence across runs.
