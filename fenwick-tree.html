Fenwick Tree (Binary Indexed Tree)

Given a 0-based logical array a[0..n−1], a Fenwick tree maintains a compact 1-based array tree[1..n] (shifting index i → j = i + 1) where each cell stores the sum of a power-of-two responsibility range a[j − lowbit(j) .. j − 1] determined by lowbit(j) = j & −j. Step through O(n) bottom-up builds, upward point updates (j += lowbit(j)), downward prefix queries (j −= lowbit(j)), and two-walk range sums prefix(r) − prefix(l − 1).

    Fenwick Tree Complexity & Binary Properties

    Operation Complexity Notes

    Keyboard shortcuts when focus is outside an input, control, or scroll region: Space play/pause, ←/→ step, Home reset.

    Why 1-Based Indexing & Two’s Complement j & −j Work

    In two’s complement, negating a positive integer j flips every bit and adds 1, leaving only the lowest set 1-bit aligned with j (e.g. 6 = 01102, −6 = …10102, so 6 & −6 = 00102 = 2). Because 0 & −0 = 0 would loop forever, Fenwick trees shift logical index i to j = i + 1 so every valid cell satisfies lowbit(j) ≥ 1.

    Responsibility Ranges (tree[j] Sums lowbit(j) Elements Ending at a[j − 1])

    Each cell tree[j] stores the sum of exactly lowbit(j) consecutive elements ending at a[j − 1]: a[j − lowbit(j) .. j − 1]. Odd indices have lowbit = 1 (single elements), powers of two like tree[4] and tree[8] cover full prefixes, and bars on the same power-of-two tier never overlap.

    Climbing Up (j += lowbit) vs Stepping Down (j −= lowbit)

    Point updates add lowbit(j) to carry past trailing 1-bits into the next higher bit, visiting every parent cell whose responsibility range covers a[i] (e.g. for i = 2, j = 3 → 4 → 8). Prefix queries subtract lowbit(j) to strip the lowest set bit, partitioning a[0..i] into at most ⌊log2 n⌋ + 1 disjoint ranges (e.g. for i = 6, j = 7 → 6 → 4).

    O(n) Build & Range Sum prefix(r) − prefix(l − 1)

    Instead of calling update n times in O(n log n), bottom-up build copies a[0..n−1] into tree[1..n] and pushes each tree[j] once into its immediate parent j + lowbit(j) in O(n). Because addition is invertible, any range sum a[l..r] takes two prefix walks: prefix(r) − prefix(l − 1) (when l = 0, the left walk starts at j = 0 and is skipped).
